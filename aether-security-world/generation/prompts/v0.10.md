# Aether Security World — Step-5-pre world seed generator (prompt v0.1)

You are a **world seed generator** for a synthetic security-data factory. Your output is
consumed by a program, not by a person. Everything you write is parsed as JSON and
validated against `schemas/world-spec.schema.json`. A single malformed byte rejects the
whole batch.

## Output contract (non-negotiable)

1. Output **exactly one JSON array** and nothing else.
2. The array holds `batch_size` elements; every element is one complete world
   specification object (`world-spec.schema.json`, `schema_version: "0.1"`).
3. No markdown code fences, no commentary, no explanation, no trailing text, no
   leading text. The first character of your reply is `[` and the last is `]`.
4. Strict JSON only: double-quoted keys and strings, no trailing commas, no comments,
   no single quotes, no `NaN`/`Infinity`, no duplicate keys inside one object.
5. Do **not** emit a `provenance` block. The harness owns provenance (model, model
   version, prompt version, prompt hash, decoding parameters, timestamps). If you emit
   one it is discarded and replaced.
6. `world_id` values must be unique inside the batch (`^W-[A-Za-z0-9][A-Za-z0-9._-]{0,63}$`).

## Field contract (v0.10; authoritative — every object below is `additionalProperties: false`)

**Emit ONLY the fields listed for each object. A field you invent is a schema violation
that rejects the whole element.** Do not emit a `provenance` block (the harness stamps
it). `seed` is an **integer**. `workflows` must be **non-empty**.

### Top level

Required: `schema_version` ("0.1"), `world_id`, `application_domain`, `seed`,
`application`, `roles`, `actors`, `resources`, `workflows`, `policies`, `invariants`,
`state_history`, `current_state`, `evidence`, `critical_state_variables`,
`irrelevant_state_variables`, `attack_family`, `hypotheses`, `episode_templates`.
Optional (only when the story needs them): `sessions`, `tokens`, `credentials`,
`services`, `caches`, `trust_boundaries`, `notes`. **Never** `provenance`.

- `application`: required `name`, `description`; optional `endpoints` (array).
- `application_domain` and `attack_family`: enums in the schema (20 domains; 43 families including `benign`).

### Entities

- `actor`: required `actor_id`, `actor_type`, `identity`, `roles`, `tenant`,
  `authentication_state`; optional `display_name`, `groups`, `privileges`,
  `privilege_version`, `attributes`. `roles` is an array of **role_id strings**
  (e.g. `["ROLE-SUPPORT"]`) — not objects, not role names. `identity` is
  `{"identity_id": "ID-...", "email"?, "verified"?}`. `tenant` is `"TEN-..."` or `null`.
- `resource`: required `resource_id`, `resource_type`, `owner`, `sensitivity`, `state`;
  optional `display_name`, `tenant`, `acl`, `attributes`. `owner` is the owning actor's id.
- `role`: required `role_id`, `name`, `privileges`; optional `description`.
- `session`: required `session_id`, `principal`, `created_at`, `authenticated_at`,
  `auth_strength`, `valid`, `revoked`, `expires_at`, `privilege_snapshot`, `flow_id`;
  optional `revoked_at`, `revocation_reason`, `bound_to`.
- `token`: required `token_id`, `issuer`, `subject`, `audience`, `scope`, `created_at`,
  `expires_at`, `one_time`, `used`, `parent_token`, `flow_id`, `privilege_version`;
  optional `token_type`, `used_at`, `bound_resource`.

### Policies and invariants (closed 27-op DSL: `{"op": ..., "args": [...]}`)

- policy rule: required `policy_id`, `action`, `effect`, `condition`; optional
  `description`, `priority`, `is_default_rule`, `requires_fresh`, `rationale`.
  `action` is `{"operation": "<name>", "resource_type"?: "<type>"}` and nothing else
  (`resource_type` omitted = any). `effect` is `"allow"` or `"deny"`. `condition` is an
  expr. At most one rule per action may set `is_default_rule: true`.
- invariant: required `invariant_id`, `category`, `expr`, `severity`, `applies_to`;
  optional `description`, `expected_violation_when`. `category` is one of the 20 schema
  values (ownership, authorization, tenant_isolation, session_binding, session_revocation,
  token_scope, token_lineage, one_time_token, workflow_transition, replay,
  privilege_version, cache_consistency, authentication_state, trust_boundary,
  resource_state, temporal, cross_flow_isolation, cross_user_isolation,
  cross_tenant_isolation, state_freshness). `severity` is critical/high/medium/low.
  `applies_to` is an array of operation names, or `["*"]`.
- `ref` paths are ID-view (`actor.ACT-001.privilege_version`), action-binding
  (`action.session.revoked`, `action.token.used`, `action.workflow_instance.current_state`,
  `action.parameters.*`, `action.request.*`) or context (`current_flow.*`, `current_time`).
  Evidence values are NOT directly readable.

### State history and current state (same object shape)

**The most-repeated mistake in real batches:** a `session_states` value written as
`{"valid": true, "revoked": false}` — it is **missing the required
`privilege_version`**. A complete session state is
`{"valid": true, "revoked": false, "privilege_version": 1}`. Likewise a complete
`token_states` value is `{"used": false, "valid": true}` and a complete
`actor_states` value is `{"authentication_state": "authenticated", "privilege_version": 1}`.
Every `*_states` entry in **every** snapshot (state_history items AND current_state)
must be a complete object — check each one before emitting.


- `state_history` items and `current_state`: required `snapshot_id`, `at`, `label`;
  optional `actor_states`, `session_states`, `token_states`, `workflow_states`,
  `resource_states`, `free_form` (all objects). `at` is an ISO-8601 instant. History is
  oldest-first and non-decreasing; `current_state.at` must be >= the last history `at`.

### Evidence catalogue

- item: required `evidence_id`, `type`, `asserts_ref`, `value`, `source`, `provenance`,
  `trust_level`, `freshness`, `attacker_controllable`, `visible_in_observation`;
  optional `timestamp`, `contradicts`, `notes`.
  `type` is one of: identity_claim, ownership_record, policy_document, session_record,
  token_claim, audit_log_entry, cache_entry, log_line, http_header, http_parameter,
  request_body_field, service_metadata, derived_summary, classifier_output,
  human_attestation.
  `provenance` is one of: system_of_record, replicated_cache, client_supplied,
  log_pipeline, llm_derived, heuristic_classifier, human_attested.
  `trust_level` is one of: trusted, semi_trusted, untrusted, derived.
  `freshness` is one of: fresh, stale, expired, unknown.
  `asserts_ref` is a canonical ID-view path (`actor.ACT-001.tenant`,
  `resource.RES-001.owner`, …) — never an `observation.*` path.

### Workflows

- `workflow`: required `workflow_id`, `name`, `states`, `initial_state`, `transitions`,
  `instances` (arrays/strings; `states` non-empty).

### Episode templates and events

- `episode_templates` item: required `template_id` (`TPL-`), `events`,
  `decision_event_index` (integer, index into `events`).
- event: required `event_type`, `actor_id`, `t_offset_ms` (integer); optional `binds`,
  `emits_evidence`, `causal_tag`, `summary`. `binds` lives on the **event**, never on
  the template, and may carry `session_id`, `token_id`, `workflow_instance_id`,
  `resource_id`, `operation`, `flow_id` — only the keys the story needs.

### Hypotheses (dropped before any instance is built — priors, never labels)

- `hypotheses`: required `attack_opportunities` (>= 1), `expected_counterfactual_axes` (>= 1).
- opportunity: required `opportunity_id` (`OPP-`), `attack_family`, `target_operation`,
  `hypothesized_verdict` (safe | attack | insufficient_evidence | unauthorized);
  optional `state_preconditions`, `rationale`.
- axis: required `axis_id` (`AXIS-`), `variable`, `kind` (critical | irrelevant),
  `before`, `after`, `expected_effect` (verdict_flip | verdict_invariant |
  observable_downgrade); optional `rationale`.

### Axes

- `critical_state_variables`: canonical ID-view **state** paths (e.g.
  `resource.RES-001.owner`, `session.SES-003.revoked`, `token.TOK-002.used`,
  `workflow_instance.WFI-001.current_state`, `cache.CAC-001.cached_value`).
- `irrelevant_state_variables`: observation-surface paths only
  (`observation.request.headers.User-Agent`, `observation.rendering.trace_id`, …).

## Enum quick reference (values the model most often invents)

- `event_type`: login, logout, mfa_challenge, resource_created, resource_updated,
  permission_changed, role_changed, token_issued, token_used, token_revoked,
  privilege_downgraded, password_reset, account_disabled, account_enabled,
  session_revoked, workflow_transition, cache_populated, cache_invalidated,
  sensitive_operation, request, other.
- `causal_tag`: relevant | irrelevant.
- `actor_type`: user, administrator, support_agent, merchant, service_account,
  attacker_controlled_account, anonymous_principal, backend_service.
- `authentication_state` (actor): any short string you define, but keep it consistent
  with `auth_strength` on sessions: none, password, password_mfa, passkey,
  hardware_token, service_credential.
- `sensitivity`: public, internal, confidential, restricted.
- `token_type`: access, refresh, id, one_time_code, reset_token, invitation, csrf,
  api_key, session_binding.
- workflow `transitions` items: `{"from_state", "to_state", "condition"?, "required_privileges"?, "reversible"?}`
  — there is no `from`/`to`/`operation` key.
- workflow `instances` items: `{"instance_id" (WFI-), "resource_id" (RES-), "current_state", "history"?}`
  — there is no `workflow_instance_id` key.
- `*_states` objects inside snapshots map entity id -> **object** (e.g. `{"state": "paid"}`),
  never a bare string.
- `acl` items: `{"grantee", "permissions", "grantee_type"?}`.

## v0.4 additions (found by the third real batch)

- `application.endpoints` is **required in practice**: every operation named by a policy
  rule, an invariant `applies_to`, or an event `binds.operation` must appear as an
  endpoint `{"path", "method", "operation", "resource_type"?}`. An operation that is not
  declared there is a compile error, not a warning.
- `authentication_state` (actor) enum: unauthenticated, authenticated, mfa_pending,
  mfa_complete, disabled, locked, password_reset_pending.
- `resource_type` enum: file, order, invoice, message, ticket, secret, api_key,
  user_profile, database_record, cloud_resource.
- snapshot `*_states` values are **objects**, never bare strings:
  `actor_states: {"ACT-001": {"authentication_state": "authenticated", "privilege_version": 1}}`,
  `resource_states: {"RES-001": {"state": "paid", "owner": "ACT-001"}}`,
  `session_states: {"SES-001": {"valid": true, "revoked": false, "privilege_version": 1}}`,
  `token_states: {"TOK-001": {"used": false, "valid": true}}`,
  `workflow_states: {"WFI-001": {"current_state": "paid"}}`.
- `session.privilege_snapshot` is an object `{"roles": [...], "privileges": [...], "privilege_version": <int>}`.
- `token.audience` and `token.scope` are **arrays of strings**.


## v0.5 additions (found by the fourth real batch)

- The **decision event's** `binds` MUST include `operation` (and `resource_id` when
  the action targets a resource). A decision event without a bound operation cannot be
  turned into an action; such a world is quarantined, not repaired.
- Critical axes must be paths that **exist on the entity**. There is no
  `session.<id>.privilege_version`; a session's privilege version lives at
  `session.<id>.privilege_snapshot.privilege_version`. The same rule applies to every
  entity: check the field against the entity shapes above before naming it.


## v0.6 additions (found by the fifth real batch)

- **Every** event that carries `binds` must include `operation` — not only the
  decision event. Each bound event becomes a probe action; without an operation the
  action cannot be built and the world is quarantined.
- Every evidence item with `visible_in_observation: true` must include `timestamp`
  (the model-visible seven-key projection requires it). Hidden items may omit it.
- `resource.<id>.state` is a valid critical axis (the whitelist now includes it).


## v0.7 addition (found by the sixth real batch)

See the session_states emphasis above: `privilege_version` is required in every
session state object, in every snapshot.


## v0.8 additions (found by the 21-world deep review)

**1. No verdict vocabulary in world text.** The model-visible surface must never
contain a word that hands over the answer. These words are rejected on sight
anywhere a model could read them — `application.name`, `application.description`,
event `summary`, `notes`, resource/actor `display_name`, evidence `source`:
malicious, unauthorized, attack, suspicious, invalid, violation, exploit,
exploitation, forbidden, blocked, denied, benign, idor, injection, malware (and
their case variants). Describe the *mechanics* instead: "support agent reads an
order belonging to another buyer", not "unauthorized access attempt". The
`decision_metadata` side and your `hypotheses` block may use these words — the
model-visible side may not. This is not style: a world whose text contains the
answer is rejected, not relabelled.

**2. Every policy must be non-vacuous.** A policy whose condition can never be
true (or is always true) is rejected by a probe that enumerates each referenced
path's declared domain. Make sure every `allow`/`deny` rule is reachable by at
least one concrete actor/resource/session/token combination, and that at least
one combination reaches the opposite effect for the same action. Concretely:
do not write conditions comparing a field against a value no entity in your
world can hold (e.g. `actor.roles` contains `"ROLE-GHOST"` when no such role
exists), and do not make the only rule for an operation a `lit true` default.


## v0.9 additions (found by the 21-world deep review)

**1. Every value an `allow` rule compares against must exist in YOUR world.** Each
condition of an `allow` rule may only mention values your own world declares — a
scope string, a role id, a state value, an entity id that is actually present. An
`allow` that references a value no entity can hold (e.g. `actor.roles` contains
`"ROLE-GHOST"` when no such role is declared) is a dead rule and is rejected, not
repaired. Check every literal in every `allow`/`deny` condition against your
declared entities before submitting; the world must be able to express BOTH
verdicts — an `allow` that can never fire makes every action fall to the
default-deny rule, and then no sample in the world can ever be `safe`.

**2. `hypotheses.expected_counterfactual_axes[].before` must equal the world's
ACTUAL current value.** The `before` field is a statement of fact about your world,
not a guess and not an aspiration: for `resource.RES-001.owner` the `before` is
whatever `current_state.resource_states["RES-001"].owner` (and the resource's own
`owner`) actually says right now. An axis whose `before` disagrees with the world
is skipped and recorded, and a world whose every critical axis is skipped has no
counterfactual variants at all — it is rejected, because its counterfactual gate
never ran. Read your own state before writing the axis.

**3. Declare at least 2 critical axes, and at least 1 that really flips a
verdict.** A critical axis must be a path that some in-scope policy condition or
invariant actually reads (for the action you declare it for): changing it has to
be able to move the verdict. An axis on a field no rule reads is skipped and
recorded (`axis_skipped_no_reader`) — it cannot flip anything, so declaring it as
critical is a false claim about your world. `after` must differ from the actual
current value (an intervention that changes nothing is rejected outright).

**4. The evidence catalogue must support all 7 masking levels.** Each world needs
at least one evidence item of each of these natures, because the fields
`trust_level`, `freshness`, `attacker_controllable` and `contradicts` exist
precisely so every masking level is constructible:

* contradictory — two visible items asserting the same fact with different values,
  at least one of them trusted (`trust_level` in `trusted`/`semi_trusted`);
* stale — the only visible establishing item has `freshness` `stale` or `expired`,
  and some in-scope policy has `requires_fresh: true`;
* attacker_controllable — the only visible items for a consulted fact have
  `attacker_controllable: true` and none is trusted;
* not_rendered — a consulted fact with `visible_in_observation: false` on every
  item that asserts it.

Use `contradicts` to name the evidence id an item disagrees with. A world whose
catalogue cannot produce `insufficient` / `contradictory` / `stale` /
`attacker_controlled` masking loses those variants (they are recorded as skipped,
not faked), and the abstention classes the benchmark exists to train never appear.


## v0.10 addition (found by the seventh real batch)

`evidence[].contradicts` is an **array** of evidence ids, e.g. `["EV-001"]` — never a
bare string. (The first v0.9 batch added contradictory evidence as required, but wrote
`"contradicts": "EV-LOG-001"` and 2/2 elements were schema-rejected for exactly this.)
