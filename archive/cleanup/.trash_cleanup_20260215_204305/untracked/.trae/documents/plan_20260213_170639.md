## 二、文件结构规划

```
backend/src/traffic-interceptor/
├── core/
│   ├── types.ts                    # 统一类型定义
│   ├── packet.ts                   # 数据包抽象
│   ├── flow.ts                     # 流管理
│   └── hal.ts                      # 硬件抽象层接口
├── platform/
│   ├── linux/
│   │   ├── ebpf-loader.ts          # eBPF 程序加载器
│   │   ├── xdp-program.c           # XDP eBPF 程序
│   │   ├── tc-classifier.c         # TC 分类器
│   │   └── af-xdp.ts               # AF_XDP socket 接口
│   └── windows/
│       ├── wfp-driver/             # WFP 驱动源码
│       │   ├── driver.c
│       │   ├── callout.c
│       │   └── communication.c
│       └── wfp-client.ts           # 用户态客户端
├── processing/
│   ├── ring-buffer.ts              # 无锁环形缓冲区
│   ├── protocol-parser.ts          # 协议解析器
│   ├── flow-tracker.ts             # 流追踪器
│   └── packet-pool.ts              # 数据包内存池
├── engine/
│   ├── fast-path.ts                # 快速路径（无状态检测）
│   ├── slow-path.ts                # 慢速路径（深度分析）
│   └── verdict-cache.ts            # 裁决缓存
├── integration/
│   ├── agent-bridge.ts             # 与 Multi-Agent 系统桥接
│   └── firewall-sync.ts            # 防火墙规则同步
└── index.ts                        # 主入口
```

## 三、实施阶段

### 阶段 1：核心抽象层
- 统一数据包类型定义
- 跨平台 HAL 接口
- 无锁环形缓冲区实现

### 阶段 2：Linux 平台实现
- eBPF/XDP 程序开发
- AF_XDP 零拷贝接口
- TC 分类器集成

### 阶段 3：Windows 平台实现
- WFP Callout 驱动开发
- 用户态-内核态通信
- 进程关联功能

### 阶段 4：处理引擎
- 协议解析器（HTTP/SQL/DNS）
- 流重组（TCP）
- 快速路径检测

### 阶段 5：智能分析集成
- 与 Multi-Agent 系统桥接
- 裁决缓存优化
- 自适应学习

## 四、性能目标

| 指标 | 目标值 |
|------|--------|
| 延迟增加 | < 100μs |
| 吞吐量 | 10+ Gbps |
| CPU 开销 | < 5% |
| 内存占用 | < 512MB |
| 丢包率 | < 0.01% |

## 五、关键技术

1. **零拷贝**：AF_XDP / WFP 共享内存
2. **无锁队列**：DPDK ring buffer 模式
3. **批处理**：批量读取/处理数据包
4. **快速路径**：无状态规则在内核态执行
5. **SIMD 优化**：协议解析向量化
