# API安全中间件管理系统用户手册

## 第4章 系统部署指南

### 4.1 部署环境要求

#### 4.1.1 硬件环境要求

系统部署的硬件环境要求根据部署规模和预期负载进行分级配置，具体如表4-1所示：

**表4-1：硬件环境配置要求**
| 部署规模 | 服务器数量 | CPU核心数 | 内存容量 | 存储空间 | 网络带宽 | 适用场景 |
|---------|-----------|-----------|----------|----------|----------|----------|
| 小型部署 | 1-2台 | 4核 | 8GB | 100GB | 100Mbps | 开发测试、小型企业 |
| 中型部署 | 3-5台 | 8核 | 16GB | 500GB | 1Gbps | 中型企业、业务系统 |
| 大型部署 | 6-10台 | 16核 | 32GB | 1TB | 10Gbps | 大型企业、云服务 |
| 超大规模 | 10+台 | 32核+ | 64GB+ | 2TB+ | 10Gbps+ | 互联网平台、金融系统 |

##### 4.1.1.1 服务器配置建议

1. **CPU配置要求**
   - **架构**：x86-64架构，支持AVX2指令集
   - **核心数**：建议4核及以上，支持超线程技术
   - **频率**：基础频率2.5GHz以上，睿频3.5GHz以上
   - **缓存**：L3缓存不少于8MB

2. **内存配置要求**
   - **类型**：DDR4或DDR5内存，支持ECC校验（生产环境推荐）
   - **容量**：根据部署规模配置，预留30%冗余
   - **频率**：不低于2400MHz
   - **通道**：建议双通道或四通道配置

3. **存储配置要求**
   - **类型**：NVMe SSD用于系统盘和数据盘
   - **容量**：系统盘不少于100GB，数据盘根据业务需求配置
   - **性能**：随机读写IOPS不低于50,000，顺序读写带宽不低于500MB/s
   - **冗余**：生产环境建议RAID 10配置

4. **网络配置要求**
   - **网卡**：千兆以太网卡起步，建议万兆网卡
   - **带宽**：根据预期流量配置，预留50%冗余
   - **延迟**：内部网络延迟不超过1ms
   - **冗余**：建议双网卡绑定，支持链路聚合

#### 4.1.2 软件环境要求

##### 4.1.2.1 操作系统要求

系统支持的主流操作系统及版本要求如表4-2所示：

**表4-2：操作系统支持列表**
| 操作系统 | 版本要求 | 架构支持 | 备注 |
|---------|---------|----------|------|
| Ubuntu Server | 20.04 LTS或更高 | x86-64, ARM64 | 推荐使用LTS版本 |
| CentOS/RHEL | 8.x或更高 | x86-64 | 企业级部署推荐 |
| Debian | 11.x或更高 | x86-64, ARM64 | 稳定性要求高的场景 |
| Windows Server | 2019或更高 | x86-64 | 特定环境需求 |
| macOS | 12.x或更高 | x86-64, ARM64 | 开发测试环境 |

操作系统配置要求：
1. **内核版本**：Linux内核5.4或更高，支持cgroups v2
2. **文件系统**：ext4或xfs文件系统，支持ACL和扩展属性
3. **安全配置**：启用SELinux或AppArmor，配置防火墙规则
4. **系统优化**：调整内核参数，优化网络和文件系统性能

##### 4.1.2.2 运行时环境要求

1. **Node.js环境**
   - **版本**：Node.js 18.12.1 LTS或更高版本
   - **包管理器**：npm 9.0.0或更高，或yarn 1.22.x
   - **配置优化**：
     ```bash
     # 调整Node.js内存限制
     export NODE_OPTIONS="--max-old-space-size=4096"

     # 优化垃圾回收
     export NODE_OPTIONS="$NODE_OPTIONS --max-semi-space-size=128"

     # 启用诊断报告
     export NODE_OPTIONS="$NODE_OPTIONS --diagnostic-report-on-fatal-error"
     ```

2. **Redis环境**
   - **版本**：Redis 7.0.8或更高版本
   - **内存配置**：根据数据量配置，建议不少于4GB
   - **持久化配置**：
     ```bash
     # 启用AOF持久化
     appendonly yes
     appendfsync everysec

     # 配置内存淘汰策略
     maxmemory 4gb
     maxmemory-policy allkeys-lru

     # 启用RDB快照
     save 900 1
     save 300 10
     save 60 10000
     ```

3. **Docker环境**
   - **版本**：Docker Engine 20.10.21或更高
   - **容器运行时**：containerd 1.6.x或更高
   - **编排工具**：Docker Compose 2.15.1或更高
   - **配置优化**：
     ```json
     {
       "storage-driver": "overlay2",
       "log-driver": "json-file",
       "log-opts": {
         "max-size": "10m",
         "max-file": "3"
       },
       "default-ulimits": {
         "nofile": {
           "Name": "nofile",
           "Hard": 65536,
           "Soft": 65536
         }
       }
     }
     ```

##### 4.1.3.3 防火墙配置

系统部署的防火墙配置建议：

```bash
# Ubuntu/Debian系统使用ufw配置
sudo ufw default deny incoming
sudo ufw default allow outgoing

# 开放必要端口
sudo ufw allow 22/tcp                    # SSH管理
sudo ufw allow 80/tcp                    # HTTP访问
sudo ufw allow 443/tcp                   # HTTPS访问
sudo ufw allow 3005/tcp                  # 后端API
sudo ufw allow from 10.0.0.0/8 to any port 6379  # Redis内网访问
sudo ufw allow from 192.168.0.0/16 to any port 9090  # 监控内网访问

# 启用防火墙
sudo ufw enable
sudo ufw status verbose
```

##### 4.2.1.2 Docker Compose配置详解

```yaml
# docker-compose.yml
version: '3.8'

services:
  # Redis服务
  redis:
    image: redis:7.0-alpine
    container_name: api-security-redis
    ports:
      - "6379:6379"
    volumes:
      - redis_data:/data
      - ./redis/redis.conf:/usr/local/etc/redis/redis.conf
    command: redis-server /usr/local/etc/redis/redis.conf
    networks:
      - security-network
    healthcheck:
      test: ["CMD", "redis-cli", "ping"]
      interval: 30s
      timeout: 10s
      retries: 3
    deploy:
      resources:
        limits:
          memory: 1G
        reservations:
          memory: 512M

  # 后端API服务
  backend:
    build:
      context: ./backend
      dockerfile: Dockerfile
    container_name: api-security-backend
    ports:
      - "3005:3005"
    environment:
      - NODE_ENV=production
      - REDIS_URL=redis://redis:6379
      - PORT=3005
      - LOG_LEVEL=info
    volumes:
      - ./backend:/app
      - /app/node_modules
    depends_on:
      redis:
        condition: service_healthy
    networks:
      - security-network
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:3005/health"]
      interval: 30s
      timeout: 10s
      retries: 3
    deploy:
      resources:
        limits:
          memory: 2G
          cpus: '2'
        reservations:
          memory: 1G
          cpus: '1'
      replicas: 2
      restart_policy:
        condition: on-failure
        max_attempts: 3

  # 前端界面服务
  frontend:
    build:
      context: ./frontend
      dockerfile: Dockerfile
    container_name: api-security-frontend
    ports:
      - "5173:5173"
    environment:
      - VITE_API_URL=http://localhost:3005
      - VITE_APP_ENV=production
    volumes:
      - ./frontend:/app
      - /app/node_modules
    depends_on:
      - backend
    networks:
      - security-network
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:5173"]
      interval: 30s
      timeout: 10s
      retries: 3

  # 监控服务 - Prometheus
  prometheus:
    image: prom/prometheus:latest
    container_name: api-security-prometheus
    ports:
      - "9090:9090"
    volumes:
      - ./monitoring/prometheus.yml:/etc/prometheus/prometheus.yml
      - prometheus_data:/prometheus
    command:
      - '--config.file=/etc/prometheus/prometheus.yml'
      - '--storage.tsdb.path=/prometheus'
      - '--web.console.libraries=/etc/prometheus/console_libraries'
      - '--web.console.templates=/etc/prometheus/consoles'
      - '--storage.tsdb.retention.time=30d'
    networks:
      - security-network
    restart: unless-stopped

  # 可视化服务 - Grafana
  grafana:
    image: grafana/grafana:latest
    container_name: api-security-grafana
    ports:
      - "3000:3000"
    environment:
      - GF_SECURITY_ADMIN_PASSWORD=admin123
      - GF_INSTALL_PLUGINS=grafana-piechart-panel
    volumes:
      - grafana_data:/var/lib/grafana
      - ./monitoring/grafana/dashboards:/etc/grafana/provisioning/dashboards
      - ./monitoring/grafana/datasources:/etc/grafana/provisioning/datasources
    networks:
      - security-network
    restart: unless-stopped

networks:
  security-network:
    driver: bridge
    ipam:
      config:
        - subnet: 172.20.0.0/16

volumes:
  redis_data:
    driver: local
  prometheus_data:
    driver: local
  grafana_data:
    driver: local
```

##### 4.2.1.4 部署操作步骤

1. **环境准备**
   ```bash
   # 安装Docker和Docker Compose
   curl -fsSL https://get.docker.com -o get-docker.sh
   sudo sh get-docker.sh
   sudo apt-get install docker-compose-plugin

   # 验证安装
   docker --version
   docker compose version
   ```

2. **下载部署文件**
   ```bash
   # 克隆项目代码
   git clone https://github.com/your-repo/api-security-middleware.git
   cd api-security-middleware

   # 创建环境变量文件
   cp .env.example .env
   # 编辑.env文件，配置实际参数
   nano .env
   ```

3. **构建和启动服务**
   ```bash
   # 构建所有服务镜像
   docker compose build

   # 启动所有服务
   docker compose up -d

   # 查看服务状态
   docker compose ps

   # 查看服务日志
   docker compose logs -f backend
   ```

4. **验证部署**
   ```bash
   # 检查服务健康状态
   curl http://localhost:3005/health
   # 预期输出: {"status":"ok","uptime":123.456}

   # 检查前端访问
   curl -I http://localhost:5173
   # 预期返回: HTTP/1.1 200 OK

   # 检查监控服务
   curl http://localhost:9090/metrics
   curl http://localhost:3000
   ```

5. **管理操作**
   ```bash
   # 停止服务
   docker compose down

   # 停止并删除数据卷
   docker compose down -v

   # 重启特定服务
   docker compose restart backend

   # 更新服务
   docker compose pull
   docker compose up -d --build

   # 查看资源使用
   docker stats

   # 进入容器调试
   docker compose exec backend sh
   ```

##### 4.2.2.2 Nginx反向代理配置

创建`nginx/nginx.conf`配置文件：

```nginx
# nginx/nginx.conf
user nginx;
worker_processes auto;
error_log /var/log/nginx/error.log warn;
pid /var/run/nginx.pid;

events {
    worker_connections 1024;
    use epoll;
    multi_accept on;
}

http {
    include /etc/nginx/mime.types;
    default_type application/octet-stream;

    log_format main '$remote_addr - $remote_user [$time_local] "$request" '
                    '$status $body_bytes_sent "$http_referer" '
                    '"$http_user_agent" "$http_x_forwarded_for"';

    access_log /var/log/nginx/access.log main;

    # 性能优化
    sendfile on;
    tcp_nopush on;
    tcp_nodelay on;
    keepalive_timeout 65;
    keepalive_requests 100;
    client_max_body_size 10m;
    client_body_buffer_size 128k;

    # Gzip压缩
    gzip on;
    gzip_vary on;
    gzip_min_length 1024;
    gzip_proxied any;
    gzip_comp_level 6;
    gzip_types text/plain text/css text/xml text/javascript
               application/json application/javascript application/xml+rss
               application/atom+xml image/svg+xml;

    # 安全头
    add_header X-Frame-Options DENY;
    add_header X-Content-Type-Options nosniff;
    add_header X-XSS-Protection "1; mode=block";
    add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;

    # 上游服务定义
    upstream backend_servers {
        least_conn;
        server backend1:3005 max_fails=3 fail_timeout=30s;
        server backend2:3005 max_fails=3 fail_timeout=30s;
        server backend3:3005 max_fails=3 fail_timeout=30s;
        keepalive 32;
    }

    upstream frontend_servers {
        least_conn;
        server frontend1:5173 max_fails=3 fail_timeout=30s;
        server frontend2:5173 max_fails=3 fail_timeout=30s;
        keepalive 32;
    }

    # HTTP服务器配置
    server {
        listen 80;
        server_name security.example.com;
        return 301 https://$server_name$request_uri;
    }

    # HTTPS服务器配置
    server {
        listen 443 ssl http2;
        server_name security.example.com;

        # SSL证书配置
        ssl_certificate /etc/nginx/ssl/fullchain.pem;
        ssl_certificate_key /etc/nginx/ssl/privkey.pem;
        ssl_session_cache shared:SSL:10m;
        ssl_session_timeout 10m;
        ssl_protocols TLSv1.2 TLSv1.3;
        ssl_ciphers ECDHE-RSA-AES256-GCM-SHA512:DHE-RSA-AES256-GCM-SHA512:ECDHE-RSA-AES256-GCM-SHA384:DHE-RSA-AES256-GCM-SHA384;
        ssl_prefer_server_ciphers off;

        # 前端代理
        location / {
            proxy_pass http://frontend_servers;
            proxy_http_version 1.1;
            proxy_set_header Upgrade $http_upgrade;
            proxy_set_header Connection 'upgrade';
            proxy_set_header Host $host;
            proxy_set_header X-Real-IP $remote_addr;
            proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
            proxy_set_header X-Forwarded-Proto $scheme;
            proxy_cache_bypass $http_upgrade;
            proxy_buffering off;
            proxy_read_timeout 300s;
        }

        # 后端API代理
        location /api/ {
            proxy_pass http://backend_servers;
            proxy_http_version 1.1;
            proxy_set_header Host $host;
            proxy_set_header X-Real-IP $remote_addr;
            proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
            proxy_set_header X-Forwarded-Proto $scheme;
            proxy_set_header Connection '';
            proxy_buffers 32 16k;
            proxy_buffer_size 32k;
            proxy_read_timeout 30s;
            proxy_send_timeout 30s;

            # 速率限制
            limit_req zone=api_limit burst=20 nodelay;
            limit_req_status 429;
        }

        # 健康检查端点
        location /health {
            access_log off;
            proxy_pass http://backend_servers/health;
            proxy_http_version 1.1;
            proxy_set_header Host $host;
        }

        # 监控端点（内网访问）
        location /monitoring/ {
            internal;
            proxy_pass http://prometheus:9090/;
            proxy_http_version 1.1;
            proxy_set_header Host $host;
        }
    }

    # 速率限制区域定义
    limit_req_zone $binary_remote_addr zone=api_limit:10m rate=100r/m;
}
```
