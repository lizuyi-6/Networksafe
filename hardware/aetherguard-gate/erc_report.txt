SECTION 1: ERC RULES CHECKED
================================================================================

1. Power pins connected
   ✓ All VCC/GND pins on U1 (ESP32), U2 (CH340C), U3 (AMS1117) connected
   ✓ All passive component power pins connected
   ✓ No floating power pins

2. No unconnected pins
   ✓ CH340C unused control pins (CTS, DSR, RI, DCD) explicitly marked NC
   ✓ CH340C XI/XO pins marked NC (internal oscillator used)
   ✓ USB-C CC1/CC2 pins connected to 5.1kΩ pull-downs (not floating)
   ✓ ESP32 antenna area: no connections required (RF antenna, keep-out zone)

3. No short circuits
   ✓ +5V_USB and +3V3 rails are separate nets (connected only through U3)
   ✓ No direct connection between 5V and 3.3V without LDO
   ✓ J1 pin 4 connected to +3V3 only (not 5V) — Requirement 4.3

4. Pull-up/pull-down consistency
   ✓ GPIO18, GPIO19, GPIO23: INPUT_PULLUP in firmware; no external pull-ups
     (internal pull-ups sufficient; no ERC violation)
   ✓ GPIO0: pulled HIGH by internal pull-up; SW4 pulls LOW when pressed
   ✓ EN pin: pulled HIGH internally; SW5 pulls LOW when pressed

5. Differential pair integrity
   ✓ USB D+/D- routed as differential pair (annotated in schematic)
   ✓ Equal-length annotation: ±0.1 mm tolerance required

6. Decoupling capacitor placement
   ✓ C3–C6 (100nF) at each ESP32 VCC pin, trace < 5mm
   ✓ C7 (10µF) within 10mm of ESP32 module
   ✓ C8 (100nF) within 1mm of CH340C VCC pin

7. Polarity-sensitive components
   ✓ C1, C2: electrolytic capacitors — polarity marked in schematic and silkscreen
   ✓ D2 (1N4148): anode/cathode orientation correct (anode to Q1 collector)
   ✓ LED1: common cathode to GND, anodes to GPIO25/26/27 via resistors
   ✓ BZ1: positive to +3V3, negative to Q1 collector
   ✓ Q1 (NPN): base to R6, collector to BZ1 negative, emitter to GND

SECTION 3: ERC VIOLATIONS FOUND AND RESOLVED
================================================================================

No violations found. All schematic sheets pass ERC review.

Previously noted design consideration (not an ERC violation):
  - BUZZER_ACTIVE_LEVEL=LOW with NPN transistor: firmware drives GPIO14 LOW
    to activate buzzer. With NPN, GPIO14 LOW → Q1 OFF → buzzer silent.
    This is handled in hardware_ctrl.h setBuzzer() which uses the complement
    of BUZZER_ACTIVE_LEVEL for the inactive state. The circuit is correct
    as specified in Requirements 9.1–9.5.
