## 第二条 保密信息定义

1. “保密信息”是指甲方、项目业主、项目相关主管部门或其授权主体向乙方披露，或者乙方在履约过程中知悉、接触、获取、推断形成的任何非公开信息，无论载体、形式或是否标注“保密”，包括但不限于：
   1. 项目信息：项目名称、招采信息、合同文本、预算、报价、项目计划、会议纪要、沟通记录、联系人、组织架构、验收标准、进度安排、项目风险、整改记录。
   2. 政府相关信息：与<span class="fill-line unit"></span>有关的未公开文件、通知、会议材料、项目汇报材料、宣传口径、内部审批流转、测试环境信息、系统配置、网络拓扑、内部联系方式、账号信息。
   3. 技术信息：源代码、受限源码、接口协议、串口协议、数据结构、数据库结构、配置文件、架构设计、算法逻辑、模型参数、规则库、编译脚本、固件、硬件原理图、PCB、BOM、调试记录、漏洞信息、密钥管理方案、OTA 方案、物理确认流程、命令签名机制、安全策略。
   4. 数据信息：日志、告警、测试样本、脱敏前数据、接口报文、账号信息、认证信息、设备标识、运营数据、审计日志、监控信息、个人信息、敏感个人信息、重要数据以及其他依法需要保护的数据。
   5. 商务信息：客户名单、供应商信息、价格体系、商务条款、采购安排、融资信息、成本结构、营销计划、案例资料、对外合作方案。
   6. 乙方衍生信息：乙方基于前述信息分析、整理、摘录、翻译、演绎、汇总形成的笔记、草稿、报告、代码、图纸、模型、测试报告、截图、录音、录像、聊天摘录、待办清单、演示文稿。
2. 以下信息不属于保密信息，但乙方应承担举证责任：
   1. 在披露时已合法公开的信息；
   2. 乙方在披露前已合法持有且能提供书面证据的信息；
   3. 非因乙方违约而进入公共领域的信息；
   4. 乙方在未使用甲方保密信息前提下独立开发并能提供完整证据链的信息。
3. 即使信息未明确标注“保密”，但结合项目背景、政府合作属性、技术敏感性、是否包含个人信息或重要数据、是否限制流转等因素，足以判断其不宜公开的，均应按保密信息处理。

## 第三条 保密目的与授权边界

1. 乙方仅得为完成本项目经甲方书面确认的工作范围之目的使用保密信息，不得用于与本项目无关之任何目的。
2. 甲方当前授权边界以甲方书面清单为准，原则上仅限：
   1. 硬件/串口协议契约；
   2. 设备接入 DTO、命令枚举、状态机说明；
   3. 脱敏后的 companion 参考实现；
   4. 甲方指定的 mock 控制平面、测试证书、测试密钥、假数据、样例文档、临时演示材料。
3. 甲方不向乙方开放以下内容，除非另有书面批准：
   1. 主仓库读写权限；
   2. 生产环境、预生产环境、政务环境或真实客户环境；
   3. 真实 API Key、设备密钥、证书、HSM、签名私钥、生产令牌；
   4. 完整数据库 schema、生产迁移脚本、真实日志、真实告警、真实固件包、真实客户数据；
   5. 鉴权、审计、租户、限流、命令签名、AI 决策、安全策略等核心实现细节。
4. 乙方仅可使用甲方书面批准的资料、环境、账号、设备、样例数据和沟通渠道开展工作，不得擅自扩张授权边界。
5. 乙方不得通过接口探测、日志比对、逆向分析、缓存残留、环境变量枚举、网络抓包、人员套取等方式突破授权边界。

   5. 向任何第三人转发、口述、展示、讲解或暗示项目名称、合作关系、项目内容或保密信息；
   6. 在简历、朋友圈、官网、宣传资料、案例集、投标文件、社交媒体、会议演讲、直播、培训材料中使用甲方或<span class="fill-line unit"></span>名称、标识、简称或暗示合作关系。
