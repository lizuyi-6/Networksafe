# generate-hard-negative v0.2

Generate a context-dependent hard negative. The attack literal must be necessary to a
realistic defensive business operation such as read-only logs, a rule editor, source
code, a unit-test fixture, a security report, an advisory, a support ticket, or an
allowlisted internal probe.

Safety must follow from endpoint semantics, identity, asset type, execution state and
authorization context. Do not make it safe merely by prefixing “tutorial”. Never use
sealed test examples. Output complete pending provenance and do not invent human
review.
